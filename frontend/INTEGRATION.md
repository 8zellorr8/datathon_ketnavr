# Подключение ИИ и бэкенда

Сейчас серверных запросов нет. UI и PDF работают с одним нормализованным результатом; демо отделено от обычных файлов.

## Единственная точка подключения

Измените `dist/analysis-client.js`:

```javascript
window.ForteLensAnalysis = {
  available: true,
  async analyze(file, { signal, onStatus }) {
    // Отправить file, получить job_id, опрашивать состояние задачи.
    // Передавать signal во все fetch и прекращать опрос при отмене.
    // onStatus('Анализируем фрагменты видео…') — реальный этап, без выдуманных процентов.
    // Вернуть нормализованный объект ниже после полного завершения.
  }
};
```

Не устанавливайте available: true до реализации метода. Настоящий файл никогда не передаётся в демо-адаптер.

## Формат результата для интерфейса

```javascript
{
  verdict: 'violation', // либо 'no_violation' со строго пустым violations
  violations: [{
    id: 'event-1',
    title: 'Краткое название предполагаемого нарушения',
    timecode_sec: 44.2,
    description: 'Конкретное наблюдаемое действие на исходной записи.',
    frames: [{
      src: 'data:image/jpeg;base64,...',
      caption: 'Кадр исходного видео, 00:44.2'
    }],
    legal: {
      act: 'Полное название акта, дата и номер',
      paragraph: 'Точный пункт и подпункт',
      url: 'https://adilet.zan.kz/...',
      context: 'Связь наблюдаемого действия с применимой нормой.'
    }
  }]
}
```

1–3 кадра на событие. Поддерживаются JPEG/PNG/WebP в data URI и изображения из /assets/ того же сайта. Дробные секунды сохраняются. Название файла, время формирования и признак demo задаёт интерфейс, а не пользовательские поля ответа сервера.

Фронтенд отклоняет неизвестный verdict, несоответствие verdict списку событий, отсутствие кадров, времени, описания, акта, точного пункта или ссылки. Ошибка анализа не превращается в отсутствие нарушений. Источники берутся из согласованного справочника команды после проверки применимости; модель не должна придумывать номера пунктов.

## Доступ к отчёту

`hasReport()` в app.js открывает отчёт только при состоянии done, verdict violation и непустом списке. Один и тот же guard проверяет кнопку, маршрут, просмотр кадров и экспорт. Выбор нового файла, отмена или новый анализ сбрасывают предыдущие данные. revision и AbortController исключают применение старого ответа; отменённый экспорт не запускает скачивание старого PDF.

Это управление интерфейсом, а не серверная авторизация. После подключения сервер обязан сам проверять доступ к задачам и данным. Долгоживущий API-ключ нельзя включать в JavaScript страницы.

## API кейса и адаптация

- `POST /api/v1/analyze`: multipart поле file, ответ job_id.
- `GET /api/v1/jobs/{job_id}`: processing, done или failed.
- На обоих маршрутах X-API-Key для API жюри.
- Результат done: verdict и violations; событие type, timecode_sec, description, evidence_frames.
- evidence_frames: 1–3 JPEG с timestamp_sec и image_base64.
- Общий лимит обработки по кейсу — пять минут с учётом очереди.

Нормализуйте ответ кейса в UI-формат внутри адаптера: например image_base64 → data:image/jpeg;base64,...; стабильный type → проверенный пункт справочника. Обязательный API жюри не меняйте ради интерфейса без проверки совместимости. Для браузера используйте подходящую серверную сессию/маршрут поверх того же сервиса анализа.

## Общий PDF

`window.ForteLensPDF.download(report, { signal })` скачивает один документ. `build(report)` возвращает Blob для самостоятельной проверки генератора. Формат report: fileName, createdAt (ISO), isDemo, violations из UI-формата выше. Локальные pdf-lib, fontkit и Noto Sans должны быть доступны по HTTP/HTTPS рядом со страницей.

Перед запуском с реальным ИИ проверьте полный цикл: выбор MOV → API → найденные события → кадры и точные источники → PDF; отдельно — отсутствие событий, ошибки, отмену, новый файл, несогласованный результат и недоступный кадр. Постоянная работа сервера и семидневная доступность — отдельный следующий этап.
