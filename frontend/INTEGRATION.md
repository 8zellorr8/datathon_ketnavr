# Подключение локального AI

Фронтенд и API обслуживает один Python сервер. В конфигурации AI `frontend_dir`
указывает на `../../frontend/dist`. Раздаются только известные CSS/JS/шрифты/ресурсы;
папки с ключами, конфигурацией и видео через статические маршруты недоступны.

## Запросы

`POST /api/v1/analyze`: multipart/form-data с полем `file`, заголовок `X-API-Key`.
Ответ 202: `{job_id,status:"processing"}`.
`GET /api/v1/jobs/{job_id}`: тот же заголовок; опрос раз в секунду.
Статусы: processing, done, failed. Общий клиентский лимит — 5 минут, включая загрузку.

Ключ вводится в поле страницы, живёт только в памяти и не попадает в URL,
localStorage или sessionStorage. Запросы идут только на origin сайта.
Ollama остаётся на loopback; браузер к ней не обращается.

## Результат

Адаптер проверяет done/verdict/violations, таймкоды и 1–3 JPEG на событие.
`type` превращается в `title`, `evidence_frames` в `frames` с data URI.
Для полного подтверждённого источника из согласованного каталога создаётся `legal`.
Если источник отсутствует, не подтверждён или недопустим, `legal:null`,
`verification_status:needs_regulation_review`. Законы и пункты не генерируются.
Статус normative_source_verified подтверждает источник, а не юридический вывод.

Модель не дообучалась при подключении сайта. Рабочий каталог покрывает только
часть размеченных событий; X-33 пока пропускается.

## Ошибки и прекращение ожидания

Ошибка, timeout, неверный JSON и нехватка памяти не превращаются в no_violation.
AbortController и revision защищают от старых ответов после нового файла/опроса.
Прекращение ожидания отменяет fetch/опрос; серверного метода отмены задания нет.

## Отчёт и PDF

Отчёт доступен только для завершённого положительного результата с событиями.
PDF включает все события, кадры, точное время и статус нормативного основания.
Библиотеки и Noto Sans загружаются локально с того же origin.
Демо доступно только по ?demo=1 и явно отделено от анализа загруженных файлов.
