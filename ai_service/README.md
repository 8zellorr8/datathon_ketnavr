Ключ формы находится в `data/runtime/api-key.txt` и хранится только в памяти вкладки.
Статические файлы раздаются по явному списку. Подробнее: `../frontend/INTEGRATION.md`.

## Рабочая папка и запуск

### Автоматический запуск на другом компьютере

Windows: откройте `Start-ForteBank.cmd`. Linux/macOS: `sh Start-ForteBank.sh`.
Нужны установленный 64-битный Python 3.10+ (рекомендуется 3.12) и Ollama.
Запускатель определяет ОС, RAM и GPU, готовит зависимости и локальные веса,
поднимает сайт/API с одного origin и сохраняет разделение исходной выборки
при переносе путей. Поддерживаемую GPU/CPU выбирает Ollama; кеш RAM зависит
от найденной памяти. Он не запускает обучение и не обещает скорость на неизвестной машине.

Только диагностика: `python Start-ForteBank.py --check`.
После первичной подготовки: `python Start-ForteBank.py --offline`.
Полная инструкция и состав переносимой папки: [docs/PORTABLE_START.txt](docs/PORTABLE_START.txt).
Запуск проверяется на Windows; реальные прогоны на Linux/macOS/AMD пока не выполнены.

### Ручной запуск на текущем компьютере

Используйте эту копию проекта, а не старую копию из Downloads:

**Терминал 1 — модель:**

```powershell
Set-Location -LiteralPath 'C:\projects\datathon_ketnavr\ai_service'
.\Start-Model.ps1
```

**Терминал 2 — UI и API:**

```powershell
Set-Location -LiteralPath 'C:\projects\datathon_ketnavr\ai_service'

```

Оставьте оба окна открытыми. Если сервисы уже запущены, второй экземпляр не нужен. Откройте [UI](http://127.0.0.1:8001). Frontend и API работают с одного origin; npm не нужен. Публичный доступ не настроен.

**Ключ — в третьем PowerShell из папки проекта:**

```powershell
Get-Content -LiteralPath '.\data\runtime\api-key.txt'
```

Вставьте ключ в поле UI и загрузите `.mov`. Страница хранит ключ только в памяти. Если `FORTE_API_KEY` не задан, `Start-API.ps1` создаёт локальный файл при первом запуске и использует его повторно. Если переменная задана, действует её значение. Ключ не включайте в исходники и общий архив.

`http://127.0.0.1:8001/health` проверяет API, не готовность модели/GPU. Реальные UI/health вернули HTTP 200. Повреждённый MOV принят с 202 и завершён `failed` без вердикта: `results/runtime/api_smoke.json`.

## Текущая конфигурация

- Ollama `127.0.0.1:11435`, `OLLAMA_NO_CLOUD=1`, один параллельный запрос и одна загруженная модель.
- Выбран `config/local.json`: контактные листы, контекст 8192, flash attention, KV `q8_0`.
- Запускатель и `Start-Model.ps1` выбирают prompt RAM cache 128 или 512 MiB: при доступной RAM менее 4 GiB либо ограниченных характеристиках — 128 MiB. Изменение действует после нового запуска Ollama; это не предел всей RAM или VRAM. Исторические прогоны и первый длинный X-14 выполнены с кешем 512 MiB.

- Эксперимент `config/individual.json` с отдельными кадрами/контекстом 16384 отклонён: X-40 завершился `failed` за 126,828 с, пик GPU 3948 MiB, свободная RAM опускалась до 864,2 MiB. Второй pilot не запускался.

## Видео длиннее минуты

Кадры декодируются по окнам с повторным использованием перекрытия. Вместо хранения всех JPEG исходные причинные кадры сохраняются как PTS и повторно извлекаются для уточнения. Исходные таймкоды и шаг выборки 4 с сохранены. Для роликов до 60 с используются окна 6 кадров/перекрытие 1; для более длинных — 12/2.

`max_refinements: null` отменяет прежний общий предел в три кандидата: все объединённые кандидаты должны пройти проверку до общего дедлайна. Явное числовое ограничение по-прежнему приводит к `failed`, если кандидатов больше. Незавершённый анализ, timeout и ошибка памяти не становятся `no_violation`.

Реальный development X-14 длительностью **142,53 с** завершил анализ за **269,672 с** (внешнее измерение с запуском процесса и аудитом — 270,422 с): 37 исходных кадров, 4 обзорных и 9 уточняющих запросов, все 9 кандидатов проверены. Все 10 JPEG/PTS совпали с исходным видео. При этом модель выдала **4 ложных события** на ролике с отрицательной меткой; пик общей GPU-памяти — 2953 MiB, свободная системная RAM падала до **8,7 MiB**. Это серьёзное давление на память, а не подтверждение устойчивой работы на слабом устройстве. Прогон использовал прежний кеш 512 MiB; новый выбор 128 MiB действует при следующем запуске модели.

Development X-39 (**78,73 с**) прошёл реальный API за **116,625 с**: 202 → processing → done/200, без ключа — 401, все 10 JPEG/PTS совпали. Пик общей GPU-памяти — 2953 MiB, минимальная свободная RAM — 1392,3 MiB. Ответ снова содержит **4 ложных события** при отрицательной метке. Артефакт: `results/long_video/X-39-api/measurement.json`.

Артефакты: `results/long_video/X-14-pilot/measurement.json` и `prediction.json`. Дополнительные проверки сохраняются в `results/long_video/`. Ограничения остаются: `.mov`, весь multipart до 64 MiB, длительность до 180 с, pipeline 270 с/API 300 с. Успех на одном ролике не гарантирует обработку всех длинных видео или работу на любом компьютере. Подробности: [docs/LONG_VIDEO.txt](docs/LONG_VIDEO.txt).

## API

```text
GET  /                          локальный UI
GET  /health                    состояние API, не readiness модели
POST /api/v1/analyze             multipart/form-data, поле file, .mov
GET  /api/v1/jobs/{job_id}        processing, done или failed
```

POST и GET jobs требуют `X-API-Key`. Пример:

```powershell
$forteKey = (Get-Content -LiteralPath '.\data\runtime\api-key.txt' -Raw).Trim()
curl.exe -X POST http://127.0.0.1:8001/api/v1/analyze -H "X-API-Key: $forteKey" -F 'file=@data/videos/Х-40.mov'
curl.exe http://127.0.0.1:8001/api/v1/jobs/JOB_ID -H "X-API-Key: $forteKey"
```

Подставьте `job_id` первого ответа вместо `JOB_ID`. При `FORTE_API_KEY` используйте ключ из переменной. При `done`: `verdict: violation | no_violation`; событие содержит `type`, `timecode_sec`, `description`, `evidence_frames` с `timestamp_sec`/JPEG `image_base64`, `rule_id`/`rule_source`. У `no_violation` список событий пуст. При `failed` вердикт не подставляется.

Один worker выполняет задачу, ещё одна может ожидать; далее 429. Весь multipart-запрос ограничен 64 MiB, видео — 180 секундами. Временный файл удаляется после обработки. Готовые результаты — в памяти до часа, максимум 100; перезапуск API их теряет. Публичный URL/HTTPS не настроены.

## Данные, анализ и ограничения

42 видео, 22 положительные/20 отрицательных меток, 40 уникальных по SHA256. Дубликаты X-4/X-47 и X-5/X-48 удерживаются вместе; у X-4/X-47 сохранены обе отметки 57/68 с. Development 26/validation 8/test 8 сгруппированы также по вручную выделенным похожим сценам. Группировка предварительная. Все описания изучались, X-26 и X-46 запускались в старом прототипе, поэтому это не слепой holdout. При inference разметка, ID и эталонные таймкоды не читаются.

FFmpeg извлекает кадры с фактическим PTS. Шаг 4 с, потоковые окна 6/1 либо 12/2 для роликов длиннее 60 с подаются контактными листами. Compact-ответ одного сегмента: до 1536 токенов, 6 наблюдений по 160 символов, summary 360, 3 кандидата по 240 символов, до 3 evidence-индексов. Ответ не обрезается ради JSON. Общий предел кандидатов отключён (`max_refinements: null`); все объединённые кандидаты уточняются ±2 с с шагом 0,5 с до общего дедлайна. Превышение времени/памяти или явного числового бюджета — ошибка. Источники правил берутся из локального каталога; кадры — фактические JPEG.

Редкая выборка, мелкие предметы и перекрытия ограничивают распознавание; confidence не калиброван. Внутренний бюджет 270 с/API300 с — ограничители со сбоем, не подтверждённая скорость. Дедлайн не гарантирует мгновенную остановку вычислений внутри Ollama. По видео нельзя установить невидимые проводки и внутренние полномочия.

В `config/rules.json` шесть правил с узкими основаниями №231; пять общих гипотез отключены. Полное нормативное покрытие размеченных нарушений отсутствует. Нельзя достраивать основание ради совпадения с меткой. Ответ — подсказка для проверки человеком.
