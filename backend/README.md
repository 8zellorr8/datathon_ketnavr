# ForteLens — Python-бэкенд на FastAPI

Слой приложения соединяет готовый AI из `ai_service` с фронтендом. HTTP обслуживает
**FastAPI + Uvicorn**. Нормативные основания берутся из локальных Python dictionaries,
без API законов, поисковых запросов или генерации пунктов моделью.

## Самый простой запуск

Нужны 64-битный Python 3.10+ (рекомендуется 3.12) и Ollama. Из корня репозитория:

```powershell
python ai_service/Start-ForteBank.py
```

Запускатель подготовит окружение, зависимости FastAPI и AI, запустит локальную модель
и Uvicorn. Первая подготовка скачивает зависимости и веса; после подготовки есть
`--offline`. Откройте **http://127.0.0.1:8001**. Вводить API-ключ на сайте не нужно.
Ключ для программных клиентов хранится локально в `ai_service/data/runtime/api-key.txt`.
Не добавляйте этот файл, видео или веса в Git.

## Запуск только FastAPI

Если Ollama и модель уже подготовлены и запущены на адресе из конфигурации:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
$env:FORTE_API_KEY = & .\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(32))"
.\.venv\Scripts\python.exe -m backend check
.\.venv\Scripts\python.exe -m backend serve --host 127.0.0.1 --port 8001
```

На Linux/macOS используйте `.venv/bin/python` и экспортируйте `FORTE_API_KEY` через
`export`. Настройки модели, каталога визуальных правил и путей берутся из
`ai_service/config/local.json`; другой файл передаётся через `--config`.
Команда `serve` сама не запускает и не скачивает модель.

- `/` — сайт.
- `/docs` — Swagger UI FastAPI; его интерфейс загружается с CDN.
- `/openapi.json` — схема API, доступная и без внешних ресурсов.
- `/health` — доступность HTTP-сервера, `framework: "fastapi"`; готовность модели этот маршрут не проверяет.

Запускайте **один процесс Uvicorn**: очередь, сессии и результаты находятся в памяти
процесса. Несколько workers или reload во время анализа не поддерживаются.

## API

| Метод и путь | Назначение |
| --- | --- |
| `POST /api/v1/analyze` | Multipart, поле `file`, MOV; ответ 202 `{job_id, status: "processing"}` |
| `GET /api/v1/jobs/{job_id}` | Статус `processing`, `done` или `failed` |
| `GET /api/v1/regulations` | Все записи нормативного справочника |
| `GET /api/v1/regulations/{rule_id}` | Основание и условия для конкретного кода |

Все `/api/v1/*` требуют `X-API-Key`. Swagger позволяет задать его кнопкой Authorize.
Браузер использует те же маршруты с префиксом `/ui/api/v1`, HttpOnly-cookie и проверкой
Origin. Доступ к результатам ограничен сессией загрузившей их вкладки/браузера;
API-ключ предоставляет служебный доступ к результатам.

Пример в PowerShell после ручного запуска:

```powershell
$headers = @{ 'X-API-Key' = $env:FORTE_API_KEY }
Invoke-RestMethod http://127.0.0.1:8001/api/v1/regulations/unattended_cash -Headers $headers
curl.exe -H "X-API-Key: $env:FORTE_API_KEY" -F "file=@clip.mov" http://127.0.0.1:8001/api/v1/analyze
```

Для запросов с телом нужен `Content-Length`; размер **всего multipart**, включая
обрамление, не более 64 МиБ. Один анализ выполняется, ещё один может ожидать.
Третий запрос получает 429. Дедлайн 300 секунд включает приём запроса и очередь;
это ограничение времени, а не обещание завершить любой ролик на любом железе.
При успехе, ошибке и завершении работы временное видео удаляется. Результаты
хранятся до часа, максимум 100 завершённых задач; после перезапуска исчезают.

Ошибки имеют форму `{"error":{"code":"...","message":"..."}}`. Ошибка модели,
нехватка памяти и timeout не становятся `no_violation`. Неизвестный код события
сохраняется в положительном отчёте с `rule_source: null` и пометкой о проверке регламента.

## Как выбирается закон

1. AI возвращает `rule_id`, описание, время и 1–3 JPEG-кадра.
2. `AnalysisService` ищет **точный** ID в `DictionaryRegulationRepository`.
3. Основание заменяется данными `REGULATIONS` и `ACTS` из `catalogue.py`.
4. Сайт получает `rule_source.title`, `section`, `url`, а также описание применимости.
5. Существующий фронтенд показывает отчёт и создаёт общий PDF со всеми событиями.

В справочнике 12 типов событий: для шести подтверждено нормативное основание,
остальным требуется проверка. `normative_source_verified` означает проверку
источника, а не окончательный юридический вывод о видео. Явное визуальное наблюдение
`needs_regulation_review` никогда автоматически не повышается до подтверждённого.
При неподдерживаемом ID ссылка не подбирается по похожим словам.

[Источники, ограничения проверки и порядок обновления](SOURCES.md).
Справочник не обновляется сам. После проверки нового пункта обновите `catalogue.py`,
версию/дату, согласованный `rule_id` и визуальные критерии `ai_service/config/rules.json`.
`python -m backend check` выявляет расхождение источников, неверные флаги и отсутствие
активных правил; эта команда не проверяет законы через интернет и не тестирует модель.

## Классы и ООП

| Файл | Ответственность |
| --- | --- |
| `models.py` | Неизменяемые `Act` и `Regulation` |
| `ports.py` | Абстрактные интерфейсы `VideoAnalyzer`, `RegulationRepository` |
| `analyzer.py` | `LocalAIAnalyzer`: адаптер существующего локального AI |
| `repository.py` | `DictionaryRegulationRepository`: поиск и защита данных от изменения |
| `service.py` | `AnalysisService`: проверка результата, времени и подбор основания |
| `auth.py` | `SessionAuthenticator`: ключи API и подписанные браузерные сессии |
| `app.py` | FastAPI, `APIRouter`, зависимости, `AnalysisController` и lifespan |
| `errors.py`, `http_errors.py` | Типизированные исключения и безопасные HTTP-ошибки |

Использованы инкапсуляция, абстракция, наследование от интерфейсов, полиморфизм
анализатора и композиция сервисов. В Python обработка исключений — `try/except/finally`.
Очередь и проверенный multipart-парсер переиспользуются из AI-сервиса; HTTP-запросы
этого приложения обрабатываются FastAPI, а не старым HTTPServer.

## Проверки и границы

Из корня репозитория после установки зависимостей:

```powershell
python -m backend check
python -m unittest discover -s backend/tests -v
cd ai_service
python -m unittest discover -s tests -v
```

Тесты бэкенда поднимают настоящий Uvicorn на свободном локальном порту и используют
управляемый анализатор. Проверяются запросы, авторизация, очередь, ошибки и основания.
Распознавание на реальных видео и качество модели эти тесты не подтверждают.

Браузерные сессии настроены для localhost и локальной сети. Публичный домен, HTTPS,
постоянный хостинг и доступ через прокси требуют отдельной настройки. На текущем
этапе это запускаемый локальный backend для хакатона, без базы постоянного хранения.
